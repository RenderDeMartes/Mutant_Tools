# Gemini Workspace - Mutant Tools

This file provides essential context and instructions for AI-assisted development within the Mutant Tools Maya rigging workspace.

## About the Project

Mutant Tools is a high-performance, block-based modular rigging system for Maya. It enables the rapid creation, modification, and extension of rigs in a non-destructive workflow, optimized for animators and riggers in demanding production environments.

**Core Features:**
- **Performance:** Blazing-fast viewport speed.
- **Modularity:** Flexible, non-destructive block system.
- **Animator-Friendly:** Intuitive controls and workflows.
- **Customizable:** Scriptable in Python for deep pipeline integration.
- **Game-Ready:** Exports to Unreal Engine and Unity.

## AI Coding Guidelines

Adhere strictly to these rules when writing or modifying code. These are a summary of the detailed docs.

### 1. Mandatory Setup & API Usage
- **Mutant API Entry Point**: Always start with the main API instance.
  ```python
  from Mutant_Tools.Utils.Rigging import main_mutant
  mt = main_mutant.Mutant()
  ```
- **Config Imports**: In any `create` or `build` block function, immediately import project configurations.
  ```python
  nc, curve_data, setup = mt.import_configs()
  ```
- **Base Validation**: In any `build` function, the first action must be to validate the scene's base setup.
  ```python
  mt.check_is_there_is_base()
  ```

### 2. Scene & Node Validation
- **Existence Checks**: **Never** assume a Maya node or attribute exists. Always guard operations with `cmds.objExists()` and `cmds.attributeQuery(..., exists=True)`.
- **Selection Safety**: Do not assume selection order or count without explicit validation.
- **Deterministic Constraints**: When rebuilding constraints, cache the type and targets (`orient`, `parent`, `point`, `scale`) and restore them explicitly with `mo=True`.

### 3. Best Practices & Style
- **Minimal Edits**: Make small, focused changes. Do not refactor unrelated code.
- **Style Consistency**: Preserve the existing coding style, naming patterns, and function signatures. The codebase mixes Python 2/3 compatibility.
- **Safe Helpers**: When creating multiple helper groups for the same control, use `mt.root_grp(input=node, custom=True, custom_name='UniqueSuffix')` to prevent name clashes.
- **Clear Feedback**: Use `cmds.warning()` for recoverable issues and `print()` for successful milestones.

## Key Files and Directories

- **`Blocks/`**: The core of the system. Contains individual `exec_*.py` scripts for rig components, each with `create_*` and `build_*` functions.
- **`Config/`**: JSON files defining naming conventions, rig setup, hotkeys, and default curves.
- **`Docs/`**: All project documentation, including the critical AI coding guidelines.
- **`UI/`**: Python source for the user interface.
- **`Utils/`**: Shared utilities and the main `main_mutant.py` API module.
- **`README.md`**: High-level project overview.
- **`easy_install.py`**: Automated installation script.
- **`INSTALLATION_GUIDE.txt`**: Manual installation instructions.
